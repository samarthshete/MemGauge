# ROADMAP.md — MemGauge

> Prioritized, one item at a time. See [STATUS.md](STATUS.md) for current reality.

## Prioritization principle

Maximize **proof of real graph-DB data modeling + real observability + a working CI gate** — the three things this project exists to demonstrate. Verify what already exists before building anything new. Avoid gold-plating and anything on the Never-build list.

- **P0** = blocks a credible demo (or the demo can't be trusted).
- **P1** = strengthens the proof.
- **P2** = polish.

## NEXT

**▶ R13 — push vector similarity into Postgres (pgvector `<=>` + HNSW).** Identified
and measured by R12: the search hot path ranks in pure Python on the API CPU, which
saturates ~8 cores under load while the databases idle. R13 moves that compute into
Postgres and re-measures. See the R13 row above and [docs/LOAD_TEST.md](docs/LOAD_TEST.md).

Also still open (optional, externally gated): the real `mem0` adapter against the
external service, which requires local `mem0ai` plus real API keys and should not be
forced into the secret-free default workflow. Use `make mem0-preflight` and
[docs/MEM0_VERIFICATION.md](docs/MEM0_VERIFICATION.md) when those credentials are available.

## Explicitly NOT doing (scope guard)

- No SPA / heavy JS frontend (the one HTML report stays server-rendered).
- No user accounts / OAuth / login.
- No additional/interchangeable databases beyond the one Postgres + one Neo4j + one Redis.
- No streaming responses.
- No reimplementation of Mem0's memory-extraction algorithm.
- No committed secrets, ever.
- No gold-plating the report UI, adding extra metrics, or generalizing the backend interface beyond what the eval needs.
